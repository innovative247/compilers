Getting Started with the Compilers

Compilers are cross-platform command-line tools for compiling SQL, managing database configurations, and running upgrades against Innovative's SBN environments. Self-contained binaries run on Windows, Linux, and macOS, with a built-in self-updater. This page covers everything from access through install, configure, every command, updating, and troubleshooting.

Repository Access

The compilers live in the private GitHub repository innovative247/compilers. You must have authorization from Innovative before you can access it — without explicit access on your GitHub account, every install URL and the auto-update endpoint return 404.

To request access:

  1. Make sure you have a personal GitHub account (github.com/signup if not).
  2. Contact your Innovative point of contact with your GitHub username and a short note about why you need access.
  3. Innovative will add you as a collaborator. Accept the invitation email within 7 days.
  4. Verify by visiting https://github.com/innovative247/compilers while signed in.

You will also need a working copy of the SBN_IR SVN tree — see Source Code (SBN_IR).

Configuration

After install, run:

set_profile configure   # Adds compilers to PATH; verifies the install
set_profile             # Interactive wizard — adds a database connection profile
runsql version          # Smoke test

settings.json

Profiles are stored in settings.json next to the binaries:

{
  "Profiles": {
    "SBNA": {
      "ALIASES": ["A"],
      "COMPANY": 999,
      "DEFAULT_LANGUAGE": 1,
      "PLATFORM": "SYBASE",
      "HOST": "10.10.10.10",
      "PORT": 5000,
      "USERNAME": "user",
      "PASSWORD": "your_password",
      "SQL_SOURCE": "/path/to/your/ir_local"
    }
  }
}

SQL_SOURCE must point at the SVN working copy from Source Code. Use set_profile to manage profiles instead of editing the file directly when possible.

Common subcommands

Every command supports:

  • version — print version
  • configure — verify install, add to PATH
  • update / install — self-update from GitHub Releases
  • help — show usage

Background builds with live tail

runcreate create_all SBNA my_run.log -bg   # launches in background
iwatch my_run.log.out                      # follows the log live

runcreate writes both .out (everything) and .err (failures only) when given a log file. iwatch waits up to 5 seconds for the file to appear, then tails until the process exits.

Updating

The compilers self-update from GitHub Releases. Run update (or install) from any binary — the dispatcher accepts the verb with any prefix:

runsql update           runsql -update          runsql --update
isqlline install        set_profile -install    runcreate /update

The mechanism queries the latest GitHub release, compares the tag against the binary's compiled-in version, and (if newer) downloads and extracts the platform-matching asset. Your settings.json is never overwritten.

A daily background check also runs on first invocation each day. If a newer release exists, you'll be prompted interactively.

MSSQL Initialization Script

For Microsoft SQL Server, the compilers honor the SQLCMDINI environment variable. If it points to a SQL file, that file runs at the start of every connection — useful for setting session options that match Sybase behavior.

Example mssql_setup.sql:

SET ARITHABORT               ON
SET ANSI_NULL_DFLT_ON        OFF
SET ANSI_NULL_DFLT_OFF       OFF
SET CONCAT_NULL_YIELDS_NULL  OFF
SET ANSI_WARNINGS            ON
SET QUOTED_IDENTIFIER        OFF

Set the variable on Windows:

[Environment]::SetEnvironmentVariable("SQLCMDINI", "C:\path\to\mssql_setup.sql", "User")

On Ubuntu:

echo 'export SQLCMDINI="$HOME/mssql_setup.sql"' >> ~/.bashrc
